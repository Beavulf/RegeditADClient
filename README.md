# RegeditAD (ClientRegAD)

RegeditAD — это внутреннее корпоративное веб-приложение, разработанное для централизованного ведения реестров сотрудников и управления их правами доступа в Active Directory. Система автоматизирует ключевые кадровые процессы, такие как приём, перевод, увольнение и стажировки, обеспечивая актуальность данных и прозрачность в управлении доступами. Благодаря использованию WebSocket, все изменения в базе данных отображаются в интерфейсе в реальном времени, создавая отзывчивый и динамичный пользовательский опыт.

## Ключевые возможности

- **Управление кадровыми событиями**: Модули для регистрации приёма, переводов (включая временные), увольнений, смены фамилии и стажировок.
- **Централизованное управление правами**: Интеграция с Active Directory для управления доступами, включая сценарии сброса паролей и контроля прав в различных системах.
- **Real-Time интерфейс**: Данные в UI обновляются в реальном времени без перезагрузки страницы с помощью WebSocket. Пользователи получают мгновенные уведомления о действиях других операторов (создание, изменение, удаление записей).
- **Контроль конкурентного доступа**: Реализован механизм блокировки записей (`is_locked`) для предотвращения конфликтов при одновременном редактировании данных несколькими пользователями. Администраторы имеют возможность управлять блокировkami.
- **Агрегированная карточка сотрудника**: Единое представление всей информации по сотруднику, собранной из различных реестров. Включает историю кадровых событий и текущий статус (активен, уволен, на стажировке).
- **Продвинутые таблицы данных**: Использование MUI X DataGrid для отображения больших объемов данных с поддержкой серверной фильтрации, сортировки, пагинации и групповых операций.
- **Экспорт данных и отчётность**: Возможность выгрузки выборок и готовых отчётов в формат Excel (с использованием ExcelJS и FileSaver).
- **Система заявок и обратной связи**: Формы для запроса доступа новыми пользователями и сбора предложений по улучшению системы с возможностью прикрепления изображений.

## Архитектура и стек технологий

Приложение построено по клиент-серверной архитектуре. Frontend, разработанный на React, взаимодействует с backend на Node.js/Express через REST API, GraphQL и WebSocket.

- **Frontend**: React 18, Vite 5 (ESM)
- **UI**: MUI (Material UI), MUI X DataGrid + Date Pickers + Tree View, Toolpad Dashboard Layout
- **Данные / интеграции**:
  - WebSocket: `react-use-websocket` (real‑time коллекции)
  - REST: `axios` (вспомогательные эндпоинты: login, feedback, выгрузки и т.д.)
  - GraphQL: `@apollo/client` (получение токена и запросы, напр. поиск пользователя в LDAP)
- **Утилиты**: dayjs/date-fns, lodash
- **Файлы**: ExcelJS + file-saver, mammoth (doc/docx)
- **Качество кода**: ESLint, `why-did-you-render` для диагностики лишних рендеров.

### Архитектурные решения

#### Real-Time с WebSocket

Основное взаимодействие для обновления данных происходит через WebSocket. Backend использует **MongoDB Change Streams** для отслеживания изменений в базе и транслирует их всем подключённым клиентам. Это обеспечивает синхронизацию интерфейсов всех пользователей в реальном времени. Клиентский `WebSocketContext` обрабатывает входящие сообщения в Web Worker для сохранения отзывчивости UI.

#### Аутентификация и роли

Реализована JWT-аутентификация. После успешного входа backend устанавливает **httpOnly cookie** с токеном, который используется для последующих запросов и авторизации на WebSocket-шлюзе. Роль пользователя (`admin`/`manager`) сохраняется на клиенте в `localStorage` и используется для разграничения доступа к разделам и функциям интерфейса.

#### Backend и интеграции

Для полноценной работы приложения требуется backend, который предоставляет:

- **WebSocket API** для CRUD-операций с коллекциями (`getCollectionMongoose`, `insertInToCollection` и т.д.).
- **REST API** для вспомогательных задач: аутентификация (`/login`), получение IP (`/adress`), отправка фидбека и выгрузка отчётов.
- **GraphQL API** для интеграции с корпоративным LDAP (поиск пользователей).

## Быстрый старт

Требования: **Node.js 18+**.

1. **Установка зависимостей:**
  ```bash
    npm install
  ```
2. **Настройка окружения:**
  - Скопируйте `.env.example` в `.env`.
    - Заполните переменные окружения, указав адреса вашего backend и GraphQL-сервиса.
3. **Запуск dev-сервера:**
  ```bash
    npm run dev
  ```
4. **Сборка для production:**
  ```bash
    npm run build
  ```

## Конфигурация (переменные окружения)

Все переменные должны начинаться с `VITE_`.

- `**VITE_SERVER_ADDRESS**`: адрес backend (HTTP + WS + static).
- `**VITE_SERVER_PORT**`: порт backend.
- `**VITE_APP_URI_GRAPHQL**`: URL GraphQL endpoint (используется Apollo Client).
- `**VITE_APP_ADMIN_LOGIN` / `VITE_APP_ADMIN_PASSWORD**`: сервисные креды для получения access token в GraphQL (токен сохраняется в `localStorage` как `authRegeditADToken`).
- `**VITE_DATE_UPDATE**`: версия/дата обновления UI (используется для бейджа `NEW` в разделе обновлений).
- `**VITE_SPRAV_MRT**`: дополнительная ссылка/путь к справочнику (зависит от окружения).

## Структура проекта (упрощённо)

- `src/App.jsx`: маршрутизация (login/dashboard/logout), провайдеры Apollo/MUI/Settings/WebSocket
- `src/websocket/WebSocketContext.jsx`: подключение к WS, загрузка коллекций, обработка сообщений (в т.ч. через worker)
- `src/components/Main/`: основной layout + навигация + уведомления
- `src/components/DataGrid/`: обёртка над MUI DataGrid, блокировки строк, групповые операции
- `src/components/regestry/`: реестры кадровых событий
- `src/components/Prava/`: права/доки/AD
- `src/components/SotrInfo/`: карточка сотрудника + экспорт в Excel
